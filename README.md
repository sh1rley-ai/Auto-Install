# AML-Guard · 金融风控智能调查与合规审查 Multi-Agent 系统

## 项目介绍

面向银行与支付机构的反洗钱与合规审查场景，输入可疑交易线索（大额异常转账、高频跨境交易等），自动完成调查规划、调单取证、多源交叉核验，输出结构化研判报告与合规审查意见。项目开源并附完整评测集。

## 技术栈

LangGraph / MCP / Rule Engine / Short-term & Long-term Memory / Evals / Python

## 个人职责

独立完成整体架构设计、多智能体编排、MCP 工具封装、记忆机制与评测体系的全流程开发与开源维护。

## 项目架构

系统将一次可疑交易调查建模为 Plan-and-Execute 多智能体协作流程，由 LangGraph 状态机编排「规划 / 执行 / 校验」三个职责分离的 Agent，工具能力统一下沉到 MCP 层，规则引擎与记忆机制作为旁路组件接入。

### 分层结构

- 入口层：接收可疑交易线索（交易流水、账户、预警类型），加载配置与案件上下文。
- 编排层（LangGraph 父图）：Planner 循环维护调查计划状态，调度 Executor 子图逐步取证，全部步骤完成后交由 Verifier 出具研判与合规意见。
- 工具层（MCP Server）：交易数据查询、监管规则库检索、名单筛查等工具经 stdio 暴露，与编排层解耦，可被任意 MCP 客户端复用。
- 旁路组件：规则引擎（确定性合规校验）、短期记忆（会话内摘要压缩）、长期记忆（标准调查路径沉淀）、审查日志（全链路 JSONL 留痕）。

### 多智能体设计

- Planner Agent：唯一职责是维护调查计划——根据线索、环境信息与长期记忆生成初始计划（可增删改步骤），依据每步取证反馈动态重规划；连续失败超阈值触发重规划，重规划超限则终止并上报人工。
- Executor Agent：唯一职责是完成当前调查步骤——CoT 推理决策后调用工具（调单、规则检索、名单筛查），观察结果决定继续、重试或宣告本步完成；步骤间清空局部上下文，避免噪音污染。
- Verifier Agent：唯一职责是校验研判结论的证据完整性——以空白上下文、对抗性立场复核每条结论是否有取证记录支撑，与 Executor 复用同一套子图代码，仅替换 prompt 与只读工具面，消除「调查者给自己打分」的自评偏差；不通过则回到 Planner 补充取证。

### 合规校验双路

- 规则引擎路：基于监管规则库对交易特征做确定性匹配（大额、跨境、结构化拆分、名单命中等），输出命中的规则条目与阈值依据。
- LLM 研判路：Verifier 结合取证证据链做情境化判断。
- 两路结论合并进入最终报告，每条审查意见附规则引用与证据出处，全流程审查日志留痕支持回溯。

### 双层记忆

- 短期记忆：单次调查内 Executor 消息超阈值时自动 LLM 摘要压缩，保留最近若干轮完整记录，防止长调查链路上下文超限。
- 长期记忆：调查成功后经 LLM 蒸馏为标准调查路径（剔除试错分支）存入库，同类案件启动前检索命中并注入 Planner 上下文，平均调查步骤下降约 30%。

### 评测体系

基于公开反洗钱数据集构建约 200 条标注测试集，案件分层抽样与补全数据均由固定 seed 驱动、原始文件以 SHA256 锁定版本，保证评测结果可复现；端到端调查准确率约 75%；评测脚本按「规划错误 / 工具调用错误 / 校验漏判 / 幻觉输出」四类归因统计失败分布，指导迭代方向。

## 快速开始

### 安装依赖

```bash
pip install -r requirements.txt
```

### 配置 API 密钥

方法 1：环境变量

```bash
export DEEPSEEK_API_KEY="your_deepseek_api_key"
export DASHSCOPE_API_KEY="your_qwen_api_key"
```

方法 2：配置文件

创建 `config/user_config.json`：

```json
{
  "ai_models": {
    "deepseek_api_key": "your_deepseek_api_key",
    "qwen_api_key": "your_qwen_api_key"
  }
}
```

### 基本使用

```bash
python main.py --show-config
```
